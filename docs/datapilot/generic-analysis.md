# 通用分析与按钮响应

系统可以分析遥测、实验、流量、运营等 CSV/XLSX 表格。销售经营分析是一个专用入口，不代表所有数据都必须是财务报表。当前分析仍以单表描述性统计、分组和图表为主，不自动完成异常诊断、复杂统计建模或因果推断。

## time_slot / value 数据怎么用

1. 选择已保存的数据集，默认进入“通用分析”。
2. 数值字段选 `value`，立即查看全表的均值、最小值、最大值、求和及缺失情况。这些来自导入时保存的统计，不需要调用模型。
3. 分组 / 横轴字段选 `time_slot`。
4. 聚合方式选“平均值”等，图表类型选择柱状图或折线图，再点击“计算分组并生成图表”。
5. `time_slot=1` 等编号按原值分组，不会被当作日历日期。折线按横轴原值排序（数值按数值、文本按文本），柱状图按聚合结果降序排列；折线横轴是分组位置，不表示实际时间间隔。

例如模拟数据：

```csv
time_slot,value
1,10
1,20
2,40
```

按 time_slot 求均值应得到：1 → 15，2 → 40。

图表仍限制 50 个类别，不静默截断。类别过多时可选择更粗的分组字段，或在 Agent 对话中明确筛选条件。通用手动表单当前不含筛选条件编辑器。

只有切换到“销售经营分析”才需要有真实日期和销售额语义。`1.0` 不能直接确定为日历日期；即使它实际代表时间戳，也需要明确单位和转换口径，不能擅自猜成某个年月日。

## 为什么点击看起来慢

2026-11-04 检查到本机使用 `make dev`，日志记录首次打开聊天页约 2.8 秒，其中约 2.3 秒用于开发编译；随后相同页面请求出现约 83～180 毫秒的记录。后续日志也有较慢的应用处理时间，因此不能把每一次延迟都归因于编译。

本轮在沙箱外测得本机 Gateway `/health` 返回 200，约 10.5 毫秒；这只能说明健康检查当时响应正常，不能替代计算请求或浏览器点击耗时的测量。未获取登录凭据或调用真实模型。

改动包括：

- 工作台、聊天等产品入口在 Next 路由等待时显示“正在打开…”，数据页和聊天页有加载占位。
- 计算立即进入处理中状态并禁用重复点击；完成后显示请求耗时（包含网络和 JSON 解析）。
- 服务端分析/图表接口返回 Server-Timing，测量该路由的计算路径，不含全部认证中间件或页面渲染时间。
- 元数据与会话选择不再读取和解析整份数据；一次计算只读取一次行数据。
- 已保存数据集不可变，前端按账号/数据集缓存预览；数据集清单保留上传后失效刷新，减少短时间重复拉取。

这些改动改善反馈并减少重复工作，不保证所有按钮已达到特定延迟。真实浏览器中的主线程、网络、服务器处理与模型等待仍应分别测量。手动数值计算不调用模型，Agent 对话则会有模型响应时间。

## 启用改动

停止旧服务，在已有便携环境的 CMD 窗口、项目根目录重新运行 `make dev`，然后刷新页面。新图表路由需要 Gateway 重启后才能使用。

继续开发时使用 `make dev`。项目稳定后，可以在停止开发服务后用仓库的 `make start` 做生产构建运行，减少开发编译开销；构建本身需要时间，这一轮没有执行生产构建。

离线验证覆盖：数字时间槽分组、通用接口所有权隔离、数据只读一次、默认模式、数值预览、处理中反馈和路由链接等待提示。真实浏览器端速度尚未复测。
